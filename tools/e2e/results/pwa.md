## Observations

- The service worker DOES register on the local server: the import.meta.env.PROD guard in src/pwa.ts is folded to true by `vite build`, and wrangler dev serves dist/client. localhost is a secure context.
- Finding (PWA-015, low severity): sw.js precaches only '/', the manifest and two icons. The hashed /assets/index-*.js and .css reach the SW cache only on the second load (or on the first offline attempt, by way of the browser's HTTP cache). Offline-after-one-visit worked in Chrome here only because the HTTP cache still held the files. If that cache is evicted (low storage, cleared data), an offline open after a single visit would load the cached '/' HTML with no JS and show a blank page. Fix: precache the entry assets (inject the hashed names into SHELL at build time, or in the install step read the cached '/' and add every /assets/ URL it references).
- Minor UX: if the connection drops while the hash is an account screen (#/signup, #/login), the app shows that screen rather than the offline card, because account screens render before the account check. A student on #/signup offline gets a form that will fail on submit (the form itself reports 'No connection').
- /api/routes answered 200 while offline from the browser HTTP cache (ETag revalidation), not from the SW; the SW never stores /api/.
- Google Fonts are cross-origin and skipped by the SW, so offline the app falls back to system fonts (cosmetic).
- Test-channel note: agent-browser `set offline on` is lost on a CLI open/reload; use an in-page location.replace() after setting it, and confirm with a fetch log.
